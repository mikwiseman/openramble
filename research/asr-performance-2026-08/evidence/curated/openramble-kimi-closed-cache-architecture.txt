Candidate product architecture:
1. During a recording, capture exposes a session-scoped lossless immutable prefix/range snapshot from RecordingPCMBuffer. Never use the lossy UI `onSamples` callback and never make disk/WAV a prerequisite.
2. A coalescing background pump sends bounded incremental PCM to the existing single persistent worker. The worker owns per-session raw audio plus exact closed TokenWindow entries and computes a window only after its silence-aligned start and complete non-final input are stable.
3. At Stop, final full audio + the same session/config generation is sent. Worker recomputes final offline plan and admits each cache entry only if window index/plan/isLast=false/config/model/language/sample hash match. Any mismatch simply recomputes that window. Existing merge/timings and final vocabulary candidateRegions/CTC remain authoritative.
4. One worker only: under-speech precompute is low-priority/coalesced. Stop may wait for an already executing ~75ms request but must supersede all queued prefix work. Never cancel an active CoreML request because supervisor cancellation kills the generation/cache.
5. Cache lifetime is exact session only; worker death, model/vocabulary/config/language change, cancellation, memory pressure, or new session invalidates it. TokenWindow cache is bounded; raw PCM max 5 minutes.
