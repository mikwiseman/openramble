# OpenRamble 0.25.1

This release makes a wrong-language transcript less likely, and explains honestly what it is.

# What changed

- A recording is now only split into pieces once it passes fifteen seconds. Everything shorter goes to the speech model in one piece, exactly as it did before 0.25.0. Splitting a short recording never saved time you could notice, and each split gives the model one more chance to choose the wrong language.

# About wrong-language transcripts

Sometimes you dictate in one language and the transcript comes back written in another — English spelled out in Cyrillic, or the reverse. This is a limitation of the speech model itself, and it is worth being precise about it.

The model chooses a single language for each recognition, and that choice turns out to depend on exactly where the recording stops. The same sentence, ended a tenth of a second earlier or later, can come back in a different alphabet. NVIDIA confirm the model cannot be told which language to use and cannot report which one it chose. Another app using the identical model produces the identical wrong output on the same audio, so this is not something OpenRamble adds.

Nothing available to us changes it: not the audio precision, not the compute settings, not a higher-precision build of the same model, all of which were measured. What this release can do is stop making it more likely, which is what the change above does.

Recognition remains fully local and offline. No dictated text or audio is added to diagnostics.
