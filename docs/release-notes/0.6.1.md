# OpenRamble 0.6.1

## Long recordings finish sooner

OpenRamble no longer runs the optional acoustic-vocabulary model across an
entire long recording when the transcript contains nothing it could correct.
It now identifies the small set of 15-second acoustic windows that can affect
the final text and evaluates only those windows, while preserving FluidAudio's
overlap behavior around every selected region.

On the controlled Apple M4 benchmark, a 183.41-second local transcription now
finishes in 1.3070 seconds at p50: 140× faster than real time and 13.4× faster
than Handy 0.9.5 on that tested recording. OpenRamble was 1.60× faster on the
tested 35.36-second recording. Handy remained 1.35× faster on the tested
5.74-second clip; the release does not turn a long-form result into a universal
claim.

The short and medium fixtures produced identical transcript hashes in both
apps. A separate 172-second recording with a real vocabulary candidate late in
its timeline also produced the same transcript hash before and after the
scheduler change.

## Cancellation stays contained

Cancelling a transcription now propagates to and drains any speculative
single-window vocabulary work before that transcription returns. Long
recordings do not start acoustic-vocabulary inference unless the transcript
contains a range that it can affect.
