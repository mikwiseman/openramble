# OpenRamble 0.24.2

This update keeps recognition responsive when the Mac is busy.

## What changed

- The Parakeet decoder no longer creates a group of spin-waiting CPU threads
  for every dictation. Short and medium dictations remain responsive under
  heavy processor pressure, with essentially unchanged idle latency.
- Recognition diagnostics now distinguish engine execution, engine-queue
  admission, Swift executor return, and MainActor return instead of grouping
  them into one unexplained interval.
- The load reproduction and log-analysis tools now separate CPU and disk
  pressure and validate nested timing spans without double-counting them.

Recognition remains fully local and offline. No dictated text or audio is
added to diagnostics.
