# OpenRamble 0.8.2

## A fresh install can no longer stall right after the download

The model would download, the setup screen would say "Preparing the model",
and nothing would happen. Restarting the app fixed it every time, which is the
tell: nothing was wrong with the files or the Mac.

Preparation asked whether the model was ready twice, of two different sources —
the app's own state and the model store's — and at the seam right after a
download those two can disagree for an instant. A disagreement was answered
with "nothing to do", and "nothing to do" is not a failure, so no retry was
ever scheduled. The app sat on a promise it had quietly stopped keeping.

There is one source of truth now, and "nothing to do" is no longer a verdict:
whenever the files are ready, the recognizer is not, and nobody gave its memory
back on purpose, preparation starts — regardless of which event was missed.
Setup also no longer counts as idle time, so the engine cannot be released
while a person is still granting permissions.

## Preparation shows where it is

It used to be a title and a number of seconds, which reads as a hang. It is
three real milestones — loading the recognizer, loading the term booster, and
one silent warm-up recognition — so the screen now shows "Step 2 of 3" with a
bar that advances as each one completes, next to the seconds.

The bar still never invents a percentage: macOS exposes no progress signal for
compiling a model, so it moves only on facts the app actually observes. And the
card no longer says "preparing" unless preparation is genuinely running; an
engine that gave its memory back after an idle period now says so plainly and
comes back on your next dictation.

All recognition remains local, and the shipping network surface is unchanged.
