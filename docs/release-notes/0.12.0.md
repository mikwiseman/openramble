# OpenRamble 0.12.0

A key that copies what you just said, and a settings window that actually
comes to the front.

## Copy the last dictation with a key

Pick a second key in Settings and it puts your last dictation back on the
clipboard. The dictation key is not among the choices, and is taken back if it
ever becomes one: a key cannot mean two things. The shortcut appears in the
menu next to the dictation it copies, so it is where you would look for it.

Off unless you choose it. A shortcut nobody asked for is a shortcut that
collides with something you already use.

## Dictations on the clipboard, if you want them

A new setting leaves each finished dictation on the clipboard as well as in the
field you dictated into. It is off by default, because the clipboard is shared
with everything else running on your Mac and what you say staying here is the
point of this app. When it is on, the text is written to this Mac only, with
the same markers that keep every other copy out of Universal Clipboard and out
of clipboard history.

## Settings opens in front

Opening Settings while another app was in front used to leave the window
behind it, and you had to hide windows to find the one you had just opened.

The cause was not where it looked. Bringing a window forward on macOS is a
request, not an instruction, and an app that lives only in the menu bar is not
granted it. So OpenRamble now takes a Dock icon for exactly as long as it has
a window open, which is what earns it the front, and returns to the menu bar
alone the moment the last window closes.

## Settings is a sidebar

The tab strip in 0.11.0 sat on a window material it would not let through,
which left a hard dark band across the top. The window uses a sidebar now — a
surface macOS gives real translucency to, rather than an effect drawn on one
that refuses it.

Dictation itself is unchanged: the hotkey, the dictionary, the history and the
recogniser are exactly as they were.
