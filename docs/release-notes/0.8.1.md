# OpenRamble 0.8.1

## Setup just works now

The first run had a stopwatch in it. Right after downloading 586 MB, the app
gave the recognizer a couple of seconds to answer, then a fixed budget of
retries a second apart — all while the Mac was still busy writing the files it
had just received. On a machine that needed a moment longer, those attempts
burned in the same busy instant, and setup stopped with everything looking
green and nothing left to do but restart the app.

Preparation no longer gives up. The files are verified; there is nothing else
for the app to do but load them, so it keeps trying with growing pauses for as
long as it is open, and the screen simply says what is true: the model is being
prepared for this Mac, with the seconds counting. No error to read, no button
to press, no state a first install can get stuck in.

The setup screen tells the same story in two honest phases — downloading, then
preparing — instead of announcing a ready model that dictation could not use
yet.

## The model downloads from the faster source first

Both sources carry byte-identical, checksum-verified files. Measured from a
fast connection, the GitHub release mirror delivered noticeably more
throughput than the Hugging Face CDN, so it now leads and Hugging Face backs
it up. Either failing still falls through to the other.

## Fewer things in the menu

Retained recovery recordings left the menu bar. A kept recording is still
announced the moment it happens and stays reachable in Settings next to the
model, so the menu can be about dictation. If recovery storage itself fails,
the menu keeps pointing at those files until it is resolved.

All recognition remains local, and the shipping network surface is unchanged.
