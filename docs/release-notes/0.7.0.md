# OpenRamble 0.7.0

## Dictation stays responsive when recognition fails

Recognition now runs in a private, persistent worker process. OpenRamble loads
and warms the primary local model before it reports dictation ready, prepares
the optional vocabulary model without making primary recognition depend on it,
keeps normal dictations on the warm path, and replaces the exact worker
generation if a Core ML request stops responding. A single stuck inference can
no longer hold every later dictation hostage.

Stopping a dictation has one foreground time budget across capture handoff,
model readiness, recognition, and insertion. If that budget expires, the
interface becomes usable again promptly and OpenRamble preserves the recording
for recovery instead of leaving “Transcribing…” on screen indefinitely.

## Short dictations finish faster

The optional custom-vocabulary model now runs only when the primary transcript
contains a phrase it can actually correct. Vocabulary forms and the exact
lexical similarity gate are cached when the dictionary changes, removing
discarded per-term work from ordinary dictations. The worker also lets Core ML
choose the available Apple accelerator rather than forcing one backend on
every Mac.

## Capture and recovery are isolated by recording

Live Float32 microphone samples go straight to recognition while the recovery
WAV is written independently. Capture queues, file operations, process I/O,
and cleanup are bounded; late callbacks are fenced by an opaque recording ID
so an old timeout cannot stop or overwrite a new dictation. Technical failures
retain recoverable audio. Once an explicit-cancellation tombstone has been
persisted, it also removes a recording created later by delayed file work or
found after relaunch; cancellation acceptance itself is not claimed to be a
power-loss durability boundary.

A single take is capped at five minutes of lossless in-memory audio. Reaching
that boundary now finishes and transcribes the complete take automatically,
rather than continuing after recovery can no longer be guaranteed.

## Focused product surface

The experimental MCP transcription server and Agents settings have been
removed. OpenRamble is focused on its core job: fast, reliable live dictation.
The dictation panel can still be placed at the top or bottom of the active
display in Settings → General.

All recognition remains local. The worker is private to its parent process,
uses anonymous pipes instead of a socket or service endpoint, and exposes no
download or network request in its protocol. The release gate also mounts the
finished DMG and makes its exact packaged worker recognize a synthetic fixture
while macOS denies all network access.
