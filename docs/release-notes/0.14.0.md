# OpenRamble 0.14.0

Dictation sometimes took several seconds to come back. This release fixes what
was actually causing it, and it was not the recogniser.

## The stall

Recognition was usually fast and occasionally many seconds slow, with no
pattern anyone could see. It was not the model warming up, and it was not the
model being reloaded — both were checked and neither matched the slow takes.

Eight hours of this Mac's own logs settled it. Across 155 dictations the
inference call itself never once exceeded 1.07 seconds. Every bit of the delay
sat *outside* the recogniser, in the gap between the microphone stopping and
the text appearing.

The cause was the microphone teardown. Stopping an audio engine can block
inside Apple's own framework — this app has known that for a long time, and
says so in a comment right above the code. What it did with that knowledge was
run the blocking call on Swift's cooperative thread pool, which has one thread
per processor core and which must never be blocked, because a blocked thread
there is not given back. The recognition waiting to finish was queued on that
same pool. So the end of one dictation could hold the result of it behind a
framework call that had gone quiet.

The evidence for that is visible in the logs: during every stall the app's
main thread kept running normally, once-a-second background checks stopped
arriving and then landed in a single burst of thirteen at once — thirteen
pieces of work that had been queued the whole time and never given a thread.

Audio teardown now runs on a thread of its own, which is allowed to block. The
same defect was fixed in the once-a-second permission check, which was parking
a pool thread on another process answering, 3,600 times an hour.

## What did not change

Nothing was removed on suspicion. The machinery that bounds how many abandoned
audio engines can exist at once stays exactly as it was: it carries a safety
property, and the tempting simplification would have quietly given that up.

## Choose your microphone

Settings now lists the inputs this Mac can hear through. A microphone you chose
that is later unplugged does not silently become a different one — dictation
continues through the system default and Settings says so, because otherwise
you would find out from the transcript.
