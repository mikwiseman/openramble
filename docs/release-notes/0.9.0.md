# 0.9.0

## A different engine, and a much quieter Mac

Recognition ran on Core ML through the Neural Engine. The first time it loaded
after macOS reclaimed memory, it did not read the model — it *rebuilt* it,
compiling the network for this particular Mac, which takes 13 to 16 seconds.
macOS purges that compiled cache exactly when memory is short, so the engine
was at its slowest precisely when your Mac was already struggling. Holding
2.4 GB of it made that struggle likelier. On Macs with 8 GB, the two fed each
other, and dictation became unpredictable: instant one minute, half a minute
the next.

OpenRamble now runs the same speech model through a different runtime, on
Metal, and compiles nothing when it loads.

| | Before | Now |
|---|---:|---:|
| Memory used | 2.4 GB | **976 MB** |
| Model load | up to 16 s | **0.29 s** |
| A half-second phrase | a full window's work | **29 ms** |

The recognition model is unchanged — the same Parakeet, the same 25
languages, the same quality — so Russian, English and speech that switches
between them mid-sentence work exactly as before.

**The model is downloaded again on this update.** It is a different file
format, about 740 MB, and the old files are no longer used.

## Everything that existed to manage the old engine is gone

Automatic eviction under memory pressure, the timed re-warm afterwards, the
separate recognition process with its own supervision and restart backoff —
all of it existed to manage 2.4 GB whose reload could cost sixteen seconds.
None of that is worth managing at 976 MB and a third of a second, and every
one of those mechanisms was a way for dictation to behave differently on two
consecutive attempts.

You keep the one control that is actually yours: **Unload model** in Settings,
where you choose when an idle model leaves memory.

## Slowness is no longer treated as failure

A recognition that took longer than expected — because the Mac was paging,
or another app was using the accelerator — used to have its engine killed and
its words withheld. That also discarded the loaded model, so the next
dictation started cold and was even likelier to be judged too slow. One slow
take could spoil several.

Whether recognition is stuck is now decided by whether it is doing work, not
by a stopwatch. A slow dictation is simply slow, and then it finishes.

## History

Settings has a **History** tab: your recent dictations with the audio that
produced them. Play a take back, copy its text, or delete it. The last five
are kept by default; you can choose up to fifty, and deleting removes the
recording as well.

This replaces a mechanism that only ever showed you a recording when
inserting the text had *failed* — invisible on the days everything worked.

**This changes what OpenRamble keeps.** Until now transcripts lived in memory
and disappeared when you quit. They are now stored on this Mac, with their
audio, until they age out of the list or you delete them. Nothing is uploaded,
and nothing ever leaves your Mac — but something now stays on it, and you
should know that before you update.

## Smaller things

- A dictation that stops while the model is still loading now says "Waking
  the model…" instead of claiming to transcribe.
- The recognition-language picker is gone. The model detects the language
  itself, including mid-sentence switches, which a forced choice could only
  make worse.
- The personal dictionary is unchanged and still applies to every dictation.

All recognition stays on this Mac. The speech runtime cannot reach the network
at all — the shipped binary is checked for that on every build.
