# OpenRamble 0.3.9

## Recovery without invented errors

Launching the app no longer shows "a recording was found after an
interruption" for recordings rescued on earlier launches — only a genuinely
new rescue is announced, and older recordings simply stay available in the
menu. Fragments too short to contain speech (an accidental key press that
survived a crash) are cleaned up silently instead of becoming a permanent
"recording after a failure". Retrying a saved recording that contains no
recognizable speech now says so plainly and deletes it, instead of failing
forever.

## Quieter, clearer menu

The menu bar menu drops its section headers: saved-work actions now name
themselves — "Insert Saved Text", "Copy Saved Text", "Transcribe Saved
Recording" — and every item uses standard macOS capitalization. Error
messages point at the menu instead of item names that no longer exist.

## Calmer recording feedback

The "No sound detected" warning is gone. Pausing to think before a phrase is
normal dictation, not an error — the live waveform already shows whether the
microphone hears you, and a genuinely silent take ends with an honest
"Nothing was recognized".

## A more welcoming first launch

Onboarding opens with a breathing microphone crest and a cleaner window
without a title bar. Steps slide like pages — forward and back along the same
path, instantly when Reduce Motion is on — with progress dots that VoiceOver
reads as "Step N of 3". The Continue button uses native Liquid Glass on
macOS 26.
