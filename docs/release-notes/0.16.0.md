# OpenRamble 0.16.0

Every dictation used to run the speech model twice. Now it runs it once.

## Two inferences where one was needed

Pressing the dictation key started a "warm-up" — a complete run of the speech
model over one second of silence — and the real dictation then waited for it to
finish before its own could begin. Every phrase you spoke was recognised
second, behind a recognition of nothing.

It hid well. The warm-up's own duration was thrown away rather than recorded,
and the waiting fell inside the part of the timing labelled "recognition" but
outside the part labelled "engine". That is why the engine figure looked
healthy — never above about a second — while dictations occasionally took
thirteen. The sacrificial first run was quietly paying whatever the measured
second one would have.

The reason it existed was Core ML: loading weights does not compile every
prediction path, so the first real dictation could be slow. That was true. It
has not been true since the Core ML engine was removed — the comment outlived
the runtime it described, and the code kept faithfully doing its job for an
engine that was no longer there.

Warming still happens where it is earned: once after the model loads, and once
after your Mac wakes. Not on every press.

## Also

The previous release moved a blocking audio-teardown call off the thread pool
that recognition waits on. Both changes attack the same measurement — the gap
between the microphone stopping and your text arriving — from different ends.
