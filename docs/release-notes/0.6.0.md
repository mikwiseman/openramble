# OpenRamble 0.6.0

> **Benchmark correction (2026-08-14):** the original Handy comparison used
> asymmetric timing boundaries and too few block-ordered repeats. Its 5.8×
> figure is retired; it must not be used in product writing.

## Local transcription for Codex, Claude Code, and other agents

OpenRamble now includes a local MCP server for transcribing existing audio
files with the model already running in the app. Access is off by default and
can be enabled in the new Settings → Agents tab, which also copies ready-made
setup commands for Codex, Claude Code, or any stdio MCP client.

Several clients can submit work at once without loading duplicate models.
Agent jobs run through a bounded serial queue, report progress and measured
timings, support cancellation, and always yield to live dictation. Files and
transcripts stay local: the helper has no network transport, staging is
private to the current macOS user, temporary audio is removed after each call,
and agent transcripts are not written to history, logs, the clipboard, or
disk.

## Put the dictation panel where it works for you

Settings → General now lets you keep the compact dictation panel at the top of
the active display or move it to the bottom. The choice follows whichever
screen you are using and stays clear of the menu bar and Dock.

## Performance claims now come with a reproducible benchmark

The repository includes a resumable benchmark runner, latency percentiles,
transcript hashes, and frozen references for real speech samples. The original
cross-app result is retired pending a persistent, paired, predecoded protocol
with identical timing boundaries and interleaved repetitions.

Audio-file decoding also rejects oversized duration metadata before allocating
the full sample buffer and observes cancellation between conversion chunks, so
abandoned or invalid agent work releases resources promptly.
