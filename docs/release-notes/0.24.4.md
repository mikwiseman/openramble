# OpenRamble 0.24.4

This update changes nothing about how dictation behaves. It removes a recognition setting that never had any effect, and writes down what we learned about mixed-language dictation while checking.

# What changed

- The speech engine was handed a language hint on every dictation, and the hint did nothing. Measured against the shipping model, asking for English, asking for Russian and letting the model decide all return identical transcripts — while a language code the model did not recognise would have failed the dictation outright. The setting is gone, along with the comments that claimed it worked.

# A known limitation, now understood

The model picks one language for an entire dictation and writes the whole take in it. When a take mixes two languages, whichever one dominates wins: English spoken inside a mostly Russian dictation comes back spelled out in Cyrillic, and a short Russian aside inside a mostly English one can be dropped altogether. Two seconds of the other language is enough to tip it.

Recognising the take in shorter pieces removes this, because each piece then gets its own decision. That is a larger change and it is not in this release.

Recognition remains fully local and offline. No dictated text or audio is added to diagnostics.
