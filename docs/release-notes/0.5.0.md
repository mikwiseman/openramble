# OpenRamble 0.5.0

## Transcribing can no longer hang forever

The worst bug a dictation app can have: you speak, the panel says
"Transcribing…", and nothing ever arrives. The cause was a recognition call
stuck on a system service that died underneath it — usually after sleep.
Every transcription now lives inside a hard deadline (twenty seconds, or
twice the length of the recording for long takes). If the engine is wedged,
the app says so, keeps the recording on this Mac, quietly rebuilds the
engine, and the next dictation runs on a fresh one. Escape still cancels
instantly, and a healthy dictation notices none of this.

## The engine warms up under your voice

The model is bimodal: a tenth of a second when warm, many seconds when macOS
has evicted it. That wait used to land in the worst place — between your
keypress and the recording. Now the keypress starts recording immediately,
always; if the engine went cold, it reloads in parallel while you speak, and
only the transcription waits for it — usually finishing before you release
the key. Loading is single-flight: however many things ask for the engine at
once, the weights load exactly once. Only the very first warm-up after
installation still blocks, and it says so honestly.

## Memory goes back on its own

No unload timers to configure. When macOS reports memory pressure, the app
releases the engine as soon as it is safely idle — immediately under
critical pressure, deliberately under sustained warning pressure, and never
on a healthy machine, because manufacturing cold starts would be worse than
using the memory. An unloaded engine never blocks dictation: the reload
rides under your next voice. At rest nothing ticks, polls, or redraws.

## The dictionary travels with you

Export your replacement phrases to a file and import them on another Mac —
two buttons in Settings → Dictionary. Duplicates are merged, nothing is
lost. The composer now reads left to right, the way you'd write the phrase.
And a term you taught the app survives every engine reload: acoustic
boosting is re-issued each time the weights come back.

## The one-hour cap is gone

A dictation used to stop itself at sixty minutes, "for safety". That was
the product deciding for you when your recording is long enough — and a
timer ticking every five seconds through every dictation to enforce it.
Both are gone. A recording ends when you end it; the transcription
budget has always scaled with the recording's length and still does.

## Silence means it worked

The chime on every start and every stop is gone. A dictation that works
shows itself — the panel while you speak, the text appearing at your
cursor — and a sound each time only teaches the ear to ignore sounds.
Now there is exactly one, quiet, and it plays only when the app has
something to say: the words did not reach the field, or nothing was
recognized. Pressing Escape stays silent; it was your decision.

## Windows open in front, and the panel can be photographed

Opening Settings used to leave you hunting for the window behind
whatever you were working in — the app has no Dock icon, so macOS never
raised it. It now comes to the front like any other app's window.

And the dictation panel is no longer hidden from screenshots. It had
been excluded from screen capture to keep dictated text out of
recordings — except it never shows dictated text, only the state and,
when something fails, the message about it. All the exclusion really did
was make failure messages impossible to screenshot and erase the panel
from every demo of the app.

## A kept recording is never a mystery file

When a failure preserves your recording, the message now says where it
lives, and Settings → About gained "Reveal Support Folder" — one click to
see everything the app stores: models and any kept recordings. Nothing else
is ever written to disk; transcripts and Recent Dictations live in memory
only and leave with the app.
