# OpenRamble 0.5.1

## Your words go straight from the microphone to the recognizer

OpenRamble used to finish recording, write a WAV file, open it again and
decode the same audio before recognition could begin. The recognizer now
receives the microphone's audio directly from memory. The recording is still
kept as a recovery path when something goes wrong, but the normal path no
longer pays for redundant file I/O and conversion.

## Ready now means the engine is actually warm

Loading the model was not the whole first-run cost: the first real inference
still had to initialize the compute path. OpenRamble now performs that warm-up
before it reports Ready, so the one-time setup no longer lands after your
first dictation. Warm-up, cancellation, model unload and memory-pressure
recovery are coordinated so none of them can leave the recognizer in a stale
state.

## Long dictations finish much sooner

Long recordings now use six recognition workers on Apple silicon, chosen from
repeatable A/B measurements on the shipping model. In our benchmark, a
three-minute recording finishes recognition in about 1.3 seconds while
producing the same transcript as the previous four-worker path. Short and
medium dictations keep the low-overhead path that is fastest for them.

## Text cleanup stays bounded

Punctuation reattachment now has a total work budget, not just per-step
limits. Unusually long or adversarial text can no longer turn cleanup into a
quadratic tail after recognition has already finished.
