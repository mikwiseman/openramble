# OpenRamble 0.8.0

## Always ready, even after macOS reclaims the memory

The speech model's compiled Neural Engine program lives in a system cache
that macOS purges under memory pressure. After such a purge, the next
dictation used to face a 13–16 second reload — and a short take could end as
a preserved recording with a notice instead of inserted text.

This release makes that scenario ordinary. The reload starts the moment the
dictation key goes down — before any other check — and rides under your
voice. If it is still finishing when you stop speaking, OpenRamble now waits
it out and inserts your words normally; nothing is dropped, and the recovery
file remains only for genuinely stuck loads. Rewarming no longer waits for
memory pressure to fully clear: a machine that hovers at the warning level
gets its engine back after a ten-second settle window, while the dictation
key always works immediately.

## The worker survives its unload

When the engine's memory is given back, the private recognition worker now
stays alive and simply drops its models. The comeback skips process launch
and framework initialization entirely, and a worker that cannot answer the
unload request within five seconds is still terminated by exact process ID,
as before. Crash recovery also respects memory pressure: a worker killed
under critical pressure is respawned only after the pressure eases, never
straight back into the starvation that killed it.

## Choose when the model leaves memory

A new "Unload model" option in Settings → Behavior returns the engine's
memory after a period of idle dictation: Never, Immediately, or after 2, 5,
10, 15 minutes, or 1 hour. The default is five minutes. "Never" keeps the
previous always-resident behavior. Holding two and a half gigabytes forever
was itself a source of the memory pressure that caused evictions; giving it
back on your schedule keeps both your Mac and your dictation fast.

All recognition remains local, and the shipping network surface is unchanged.
