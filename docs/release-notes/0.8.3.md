# 0.8.3

## Setup no longer waits for something that is not happening

On a fresh install, setup could stop for good: the model card said "Model ready",
both permissions were granted, and Continue stayed grey under the words "Getting
the model ready…". Only quitting and relaunching cleared it.

Nothing was preparing the model at that moment. When the Mac runs low on memory —
likely right after a 586 MB download while the model is being compiled for this
particular Mac — the app lets the recogniser rest until it is next needed. That is
the right thing to do for memory. But the setup screen was waiting for a loaded
recogniser, and the only things that wake one are pressing the dictation key or
switching back to the app, neither of which happens while a person sits on the
setup screen. Two sensible rules held each other.

The previous two releases each closed one way *into* that state, and it came back
through another door. This release removes the requirement instead: **no part of
the first run asks for a loaded recogniser any more.** Setup needs the permissions
and the model files, nothing else. The recogniser loads when it is actually needed,
and dictation already waits for a cold one and inserts the text when it arrives —
so a condition that cannot deadlock replaces one that had to be rescued.

## One answer per question

The menu, the setup card and the try-out step used to describe the model's state
separately, and could disagree — which is how one screen came to say "Model ready"
and "Getting the model ready…" at the same instant. They now all read the same
sentence from the same place, so they cannot contradict each other.

The try-out step also shows the first compile while it happens, instead of leaving
a person to wonder why their first attempt is slow.

## Under the hood

New tests hold the setup screen to a rule it can be measured against: at every
moment it either lets a person move on, or is blocked by work genuinely in motion
and says truthfully what that work is. A screen waiting for work nobody performs
now fails the suite, and so does a card that contradicts its own footer.
