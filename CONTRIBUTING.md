# Как участвовать

Спасибо за интерес. Ниже — то, что стоит знать до первого изменения.

## Главное правило

Продукт обещает, что речь пользователя не покидает его компьютер. Всё остальное
подчинено этому.

Разрешены ровно два места, откуда приложение ходит в сеть: загрузка модели по
кнопке (`LocalASR/ModelDownloading.swift`) и обновления с согласия пользователя
(`SparkleUpdater.swift` — это и проверка ленты, и загрузка образа). Любой новый
сетевой вызов будет отклонён, и автоматическая проверка не даст его смержить.

## Что точно не примут

- Аналитику, телеметрию, отчёты о сбоях в чужой сервис.
- Логирование распознанного текста, отдельных слов или имён файлов пользователя.
- Запись в буфер обмена мимо `prepareForNewContents(with: .currentHostOnly)` —
  обычная запись отдаёт диктовку в Universal Clipboard на все устройства.
- Синхронизацию настроек или истории через iCloud.
- Новые зависимости без предварительного обсуждения в issue.

## Как устроен код

- `Packages/DictationCore` — логика без AppKit и без распознавания. Здесь же
  контроллер диктовки. Тесты идут за секунды, потому что система подменена
  протоколами.
- `Packages/LocalASR` — установка модели и распознавание. Единственный
  `import FluidAudio` — в `FluidAudioAdapter.swift`.
- `apps/macos` — тонкий слой: интерфейс и реализации системных краёв.

Зависимость направлена от `LocalASR` к `DictationCore`, не наоборот. Иначе
тесты чистой логики тянули бы за собой модель.

## С чего начать

Нужен Xcode с тулчейном Swift 6 и `brew install xcodegen`: файла проекта в
репозитории нет, он генерируется из `apps/macos/project.yml`. Правки вносятся
в `project.yml`, а не в сгенерированный `.xcodeproj` — последний перезаписывается.

```bash
git clone https://github.com/mikwiseman/wai-dictation.git
cd wai-dictation
swift test --package-path Packages/DictationCore   # секунды, модель не нужна
cd apps/macos && xcodegen generate && open WaiDictation.xcodeproj
```

Модель нужна только для настоящей диктовки — её ставит само приложение по
кнопке. Тесты и проверки её не требуют, кроме `test-zero-network.sh`.

Приложение живёт в строке меню и не показывается в Dock (`LSUIElement`). При
первом запуске оно попросит микрофон и универсальный доступ. Отладочная сборка
идёт с идентификатором `is.waiwai.dictation.dev`, поэтому разрешения ей нужно
выдать отдельно от релизной — система считает их разными приложениями.

## Перед отправкой изменений

```bash
swift test --package-path Packages/DictationCore
swift test --package-path Packages/LocalASR
./scripts/check-network-surface.sh
```

Если трогали приложение — соберите его:

```bash
cd apps/macos && xcodegen generate
xcodebuild -project WaiDictation.xcodeproj -scheme WaiDictation \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build
```

Если трогали распознавание или установку модели — прогоните ещё и проверку
главного обещания. Ей нужна уже установленная модель, и идёт она несколько
минут:

```bash
./scripts/test-zero-network.sh
```

CI на каждый pull request гоняет всё, кроме последнего: оба пакета, сборку
приложения, сетевую поверхность и сборку `LocalASR` отдельно под arm64 и под
x86_64. В пакетах предупреждения компилятора там считаются ошибками. Проверку
без сети CI сделать не может — на бегунке нет установленной модели, поэтому
она остаётся ручной.

## Стиль

Сначала падающий тест, потом код. Решения выносятся в чистые типы с тестами, а
не прячутся внутри вью-моделей: почти все правила диктовки пришли из реальных
багов, и каждое стоит закрепить проверкой.

Ошибки должны доходить до пользователя. Молчаливое «ничего не произошло» — худший
из возможных исходов: человек продиктовал минуту и не знает, что она пропала.

Комментарии объясняют, **почему** так, а не что делает строка. Особенно там, где
поведение системы неочевидно — таких мест в проекте хватает.

## Про записи голоса

Не прикладывайте к issue и pull request аудиозаписи и продиктованный текст.
Для воспроизведения хватает описания словами.
